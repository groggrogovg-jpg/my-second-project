Ты — ИИ-помощник по разработке на Replit. Мы модернизируем существующее веб-приложение для создания карточек товаров (маркетплейсы). Сейчас у нас есть редактор изображений, в котором можно загружать фото. Нужно добавить новый функционал: замену фона и сопутствующие инструменты.

ВАЖНО: Мы НЕ меняем никакие другие части приложения (генерация карточек, личный кабинет, пакеты звёзд и т.д.) — только расширяем возможности редактора изображений.

Реализуй следующие функции строго по этапам (приоритетность):

### ЭТАП 1 (Первая очередь — база, закрывает 80% потребностей):
1. **Автоматическое удаление фона** – пользователь нажимает кнопку, и нейросеть (или алгоритм) вырезает объект, оставляя прозрачный фон. Используй библиотеку `@imgly/background-removal` или аналогичную (можно подключить через CDN). После удаления фон становится прозрачным (PNG).
2. **Заливка белым фоном** – после удаления или в любой момент пользователь может выбрать однотонный фон (по умолчанию белый, но можно и другие цвета). Реализуй как выбор цвета из палитры или заливка текущего фона указанным цветом.
3. **Ручной «Ластик»** – инструмент для точечной доработки: пользователь может закрасить лишние участки (артефакты) прямо на холсте, стирая их к прозрачности. Размер кисти регулируемый.

Интерфейс: все кнопки должны быть в отдельной панели «Фон» внутри редактора. После применения каждой операции пользователь должен видеть результат на холсте.

### ЭТАП 2 (Вторая очередь — визуальный апгрейд без сложной разработки):
4. **Готовые шаблоны фонов** – 5–10 предустановленных фоновых сцен (студийный белый, серый градиент, деревянная текстура, природа, витрина). Пользователь выбирает шаблон, и фон заменяется на него (товар остаётся поверх). Шаблоны хранятся как изображения в папке `public/backgrounds`.
5. **Автоматическое добавление тени** – после смены фона добавляется мягкая реалистичная тень под объектом (можно использовать фильтр `drop-shadow` CSS или генерация тени на холсте через библиотеку). Тень должна быть настраиваемой (интенсивность, смещение, размытие).

### ЭТАП 3 (Третья очередь — профессиональные фичи):
6. **Генерация фона по тексту (ИИ)** – пользователь вводит текстовое описание (например, «уютная комната с камином»), и нейросеть (например, через API Replicate или Stability AI) генерирует уникальный фон, который применяется к изображению. Предусмотри индикатор загрузки и обработку ошибок.
7. **Пакетная обработка** – пользователь выбирает несколько загруженных изображений (до 10) и применяет к ним выбранные действия (удаление фона, заливка цветом, шаблон, тень) одновременно. После обработки все файлы можно скачать архивом.

---

### ЛОГИКА СПИСАНИЯ ЗВЁЗД (монетизация):
- Каждое действие в редакторе (кроме предпросмотра) **списывает звёзды** с баланса пользователя. Номинал списания зависит от типа действия и пакета пользователя (как при генерации карточки).
- **Тарифы списания** (примерные, можно будет менять в настройках):
  - Удаление фона – 1 звезда
  - Заливка цветом – 0.5 звезды
  - Ластик (на каждое применение, не на каждое движение) – 1 звезда
  - Шаблон фона – 2 звезды
  - Тень – 1 звезда
  - Генерация фона по тексту – 5 звёзд
  - Пакетная обработка (за каждый файл) – по тарифу каждой операции, но с коэффициентом 0.8 (скидка за пакет)

- **ВАЖНО**: перед любым действием, которое тратит звёзды, должно появляться **предупреждение** (модальное окно или тост) с текстом:  
  *«Это действие спишет [количество] звёзд с вашего баланса. Продолжить?»*  
  У пользователя должны быть кнопки «Отмена» и «Подтвердить». Если звёзд недостаточно — показывать ошибку и предложение пополнить баланс.

- Списание происходит **только после успешного применения** операции (если операция не удалась — звёзды не списываются).

- Баланс звёзд хранится в базе данных (например, Supabase или Firebase) и обновляется асинхронно. После каждой операции обновлять отображение баланса в интерфейсе.

- Вся логика списания должна быть вынесена в отдельный сервис (функция `deductStars(userId, amount, actionType)`), чтобы она использовалась и для генерации карточек (как у вас уже есть), и для редактора.

### ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ:
- Фреймворк: React (предполагаем, что у вас уже он). Если нет — адаптируй под текущий стек (уточни у разработчика).
- Работа с изображениями: используй `canvas` или библиотеку `fabric.js` для манипуляций. Для удаления фона — `@imgly/background-removal` (можно установить через npm). Для шаблонов и генерации — стандартные fetch-запросы.
- Все изменения должны быть реактивными (состояние редактируемого изображения хранится в стейте).
- После завершения редактирования пользователь может сохранить результат (скачать) — это бесплатно, звёзды не тратятся.
- Интерфейс редактора должен оставаться интуитивно понятным, добавить подсказки (tooltip) для новых функций.

- НЕ трогать код, отвечающий за генерацию текстовых карточек, личный кабинет, страницы тарифов, авторизацию и т.д. — только расширять редактор изображений.
- НЕ переопределять существующие кнопки, только добавить новые в панель инструментов.

- При первом запуске после внедрения — никаких миграций базы не требуется, только добавить поля для баланса (если ещё нет), но это уже есть, так как у вас уже есть звёзды.
